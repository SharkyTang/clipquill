## S4：真实来源与任务边界

`tool.js` 沿用 `resolve-douyin`、`login-douyin` 和原服务 API。支持分享全文；多个不同 HTTPS 链接明确拒绝，不悄悄选第一条。已打开作品仍只查询已有抖音权限范围并过滤作品 ID，不抓扩展自身。来源列表增加请求代次，较早返回的列表不能覆盖后选来源。

独立下载不连接识别服务；提取仍按原 `video.mjs` 每次检查完整文件并复用，缺失时才下载。解析后立即展示原响应中已有的标题与规格；复用后更新实际规格。没有扩充封面/作者协议，没有加假播放器、多平台或下载前置步骤。

同一工具页立即锁定重复提交和任务参数，执行期间仍可编辑旧稿。操作/来源代次与 pagehide 检查阻止迟到 UI 写入或离开后继续创建新请求；页面离开不等于取消服务计算。来源变化清除旧视频卡并提示等待，文案仍标明自己的作品。

轮询同时核对 workId 和确切 job id，展示真实 `stage`；只有有效 startedAt 才显示耗时。相同阶段的秒数变化不持续读屏播报；新阶段/完成/错误才恢复通知。没有虚构百分比或取消按钮。

轮询连接失败标为“状态待确认”，重试只 GET 原任务。只有明确失败、且保留的操作确切属于该 job，才允许按原参数重新提取。POST 响应丢失、损坏 JSON 或畸形任务数据均按“提交结果待确认”处理，不盲目重提；用户明确核对后方可解锁手动提交。

**协议限制仍在：** 服务没有客户端幂等键或查询“刚刚提交但无 ID 的任务”接口。上述保护作用于当前页面，不能证明响应丢失后服务未创建任务，也不承诺跨页面/重开后的全局幂等性；未改后端来隐藏这个限制。

连接状态采用请求代次，旧健康请求不能覆盖新状态。音频的同任务在途请求复用，折叠后暂停并禁止迟到音频激活，旧任务响应不会撤销或替换新任务的音频。

## S5：当前稿与字幕映射

新增 `editor.mjs`，只适配编辑事件，不改 `draft.mjs` 的时间映射：

- 原 textarea 保留；输入法组合期间不重写 value/选区或保存中间拼音，compositionend 后提交一次，忽略重复尾随 input。
- full/segment 编辑统一进入原 `editFullText`/`editBlock`。分段 textarea 也只在内容实际不同时写 value，避免每次输入重置光标和撤销。
- 原生 historyUndo/historyRedo 优先恢复当前任务的内存映射快照，修正原先整稿撤销把所有区间合并的问题。每个活动历史栈最多保留 120 个快照、累计 2,000,000 个 UTF-16 字符预算；整稿和当前分段栈分别计数，单份当前文档超过预算时仍保留一份映射。超过缓存时按原保守编辑映射并明确提示检查时间。
- 快照只在内存，按 jobId/sourceSignature 隔离；原 sources/端点不变，跨段仍合并原区间，新增文字仍归属原区间，不平均重估时间。
- pagehide 对仍可见的组合输入做同步、尽力的最终保存；不保证浏览器一定派发生命周期事件或存储配额一定可用。

新完成结果遇到已编辑稿、组合输入、保存失败或来源变化时，先进入“待载入”提示。明确点击载入前再次安全保存当前稿；保存失败时保留两份内存结果，不替换原编辑器。保留当前稿后仍可尝试查询服务上的新结果；任务引用写入失败时只承诺本页的内存恢复，不承诺重开恢复。

缓存与引用写入按顺序确认：新结果缓存失败不推进 lastCompleted-v1，保存当前稿时会补试缺失的结果/引用，全部成功才标已保存。损坏的当前稿 JSON 显示回退警告，在既有 draft-rejected-v1-* 键保存恢复副本，原坏记录不在打开时覆盖或清除。

复制/TXT/SRT 使用当前稿；组合输入未完成会明确等待。无法映射的当前输入保留并可复制/TXT，拒绝伪造 SRT。复制晚回调不覆盖新任务状态；导出失败保留内容、回收 Blob URL，不宣称磁盘已保存。旧字幕、双模型分歧、重点片段、人工确认、回听与辅助术语入口保留；没有新造历史数据库或剪辑时间轴。
