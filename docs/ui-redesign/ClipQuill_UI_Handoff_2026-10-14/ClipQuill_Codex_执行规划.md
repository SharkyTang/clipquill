# ClipQuill UI 重构：Codex 分阶段执行规划

**版本：** 1.0  
**日期：** 2026-10-14  
**对象：** ClipQuill 浏览器扩展及其现有扩展页面  
**任务：** 在保留下载、转写、文案编辑和导出能力的前提下，重构布局、品牌图标和深浅主题。

> **产品边界：ClipQuill 是浏览器插件；FrameWeave 映构是另一个私人桌面工作台。此次只修改 ClipQuill。不要创建 Electron/Tauri 桌面应用，不要加入 FrameWeave 的 AI 视频分析、创作知识库、脚本策划等功能。**
>
> **实施前提：本文件依据用户提供的现有页面截图、两张已选定参考图及此前描述编写，尚未读取实际仓库。文中组件名、目录名与状态名是建议接口，不是对现有代码的断言。Codex 必须先审计仓库，再映射至真实入口、技术栈和数据结构。**

### 0.1 已确定的设计决定

- 产品名称统一为 `ClipQuill`，不使用 `ClipQuill Capture`，不使用「抖音视频与文案 · 本地简化版」作为正式 UI 名称。
- 保留羽毛笔与播放符号的组合，不改回青绿色 C 形标，不重新发散其他 Logo 方案。
- 大窗口使用三块横向区域：紧凑导航、视频信息/操作、文案主工作区。这里的“三栏”不等于新增三个产品模块。
- 支持完整浅色与深色主题；主题切换只改变 ClipQuill 页面，不改变抖音网页或 Chrome 本身。
- 只做 UI、品牌和必要的薄适配层；不顺便重写下载与识别引擎。

### 0.2 本文件补充的实施默认值

以下是为减少开发歧义而给出的默认方案，不代表用户此前逐项确认过：增加「跟随系统」选项并作为首次默认；主按钮采用可读性更好的实色蓝紫；宽屏导航约 184px、视频栏约 320px；先完成 S0–S3 作为第一次视觉检查点。这些可在视觉验收时微调，但不能侵占产品范围。

## 1. 范围与禁止事项

### 1.1 本轮必须完成

| 领域 | 交付要求 |
|---|---|
| 品牌 | Logo 矢量源、多尺寸 PNG、扩展名称、页面标题、favicon、工具栏图标一致 |
| 布局 | 扩展完整页面使用新布局；现有侧栏/弹窗入口按实际宽度自适应 |
| 主题 | 深色、浅色、跟随系统；持久化、跨已打开扩展页面同步、完整控件覆盖 |
| 主流程 | 粘贴分享内容、选择已打开作品、下载视频、提取文案的真实入口继续可用 |
| 文案 | 编辑、复制、TXT/SRT 导出、恢复已有文案及现有回听校对能力保留 |
| 状态 | 空态、处理中、完成、失败、服务未连接、保存失败等真实状态 |
| 工程质量 | 可维护样式变量、可访问交互、回归测试、截图与交接记录 |

### 1.2 本轮不做

不新增多平台下载适配器，不把参考图中的 B 站/YouTube 宣传当作已实现能力；不加入 AI 分析、热点发现、自动创作、FrameWeave 导入接口；不开发云账号、付费、同步服务器或复杂任务管理系统；不增加剪辑软件式可拖拽时间轴；不迁移框架、打包器、数据库或 Python 服务；不自动发布商店版本、推送远程仓库或处理 API 密钥。

**已有且真实可用的功能不得因“本轮不新增”而删除。** 例如仓库确实已有双模型校对，就保留其能力和入口；尚无该能力则不为匹配设计图补出假按钮。

### 1.3 保留的底层契约

先定位并记录，再尽量保持以下项目不变：下载链路与文件命名；任务创建、查询及取消协议；本地服务地址和端口；识别模型与参数默认值；音频处理、字幕对齐、双模型校对逻辑；编辑稿与字幕段映射；文件复用策略；存储键、数据格式和版本；权限、扩展入口与消息名称。

此前描述中的 `127.0.0.1:8766`、Python/FFmpeg/本地语音模型只作为查找线索。**以仓库配置为准，不在 UI 中重新硬编码，更不要将本地服务改成监听所有网卡。**

## 2. S0 审计时必须先确认的事实

### 2.1 入口与技术栈盘点

读取仓库根目录与相关子目录的 `AGENTS.md`（若存在），然后查看 README、manifest、现有包配置和运行脚本。按项目当前技术栈工作，不强制使用 React、Vue、Tailwind 或任何指定组件库。关于 Codex 项目指令文件可参阅官方说明。[^codex-agents]

至少识别：

| 审计项 | 要记录的结果 |
|---|---|
| 页面宿主 | 独立扩展标签页、`side_panel`、action popup、options page 各自是否存在 |
| UI 入口 | 实际 HTML/JS/CSS 或框架入口，以及入口之间是否共用组件 |
| 背景逻辑 | Service Worker、content script、消息桥、长任务实际由谁执行 |
| 后端边界 | 现有请求、响应、错误和进度字段；哪些步骤并不提供百分比 |
| 持久化 | 文案、原始字幕、当前任务、历史记录分别存在哪里 |
| 外部依赖 | 现有本地服务、模型、FFmpeg、权限；缺失项记为环境限制 |
| 测试与构建 | 真实可执行命令，已有 fixture、测试框架、打包方式 |

**不要因为参考图像桌面软件，就把当前扩展迁移成桌面应用；也不要因为只看到宽屏图，就删掉已有 Chrome 侧栏入口。**

### 2.2 功能基线与证据分级

用户现有截图显示了链接输入、下载/提取文案、辅助选项、已打开作品选择、完成状态、恢复上次文案、编辑器、复制/TXT/SRT、回听校对折叠区及作品元数据。这只是现有界面的证据，运行结果仍需测试。

对每一项分别标注 `已运行验证 / 有实现未验证 / 仅 UI / 不存在 / 环境阻塞`。不得把早期的失败尝试、旧文档中的设想或设计图上的文案当作当前事实。

基线至少验证：一个支持的链接、一份已存在文案、一次编辑后 TXT 导出、一次编辑后 SRT 导出、恢复上次文案，以及本地服务未启动时的表现。有可用授权测试视频时，再验证完整下载→识别流程。无法联网或缺少服务时，记录具体阻塞，不声称已通过。

### 2.3 保护用户工作区

先查看 Git 状态和已有改动；不要覆盖无关文件、删除未提交修改、运行 `git reset --hard` 或 `git clean -fd`。不要清空浏览器配置、文案数据、模型缓存或下载目录。不自动安装/升级识别环境，也不结束用户运行中的服务。

审计输出建议保存为 `docs/ui-redesign/baseline.md`，记录真实路径、可用命令、能力矩阵、风险和 UI 改动边界。目录可随项目惯例调整。

## 4. 布局尺寸、滚动与响应式

以下单位均为 **CSS px**，不是截图导出的物理像素。禁止用绝对定位照着 1536×1024 大图逐个描坐标。

### 4.1 桌面布局默认值

| 项目 | 默认值与范围 |
|---|---|
| 左导航 | 184px，可在 168–200px 内微调 |
| 顶栏 | 56px |
| 主区外边距 | 24px，窄窗口降至 16px / 12px |
| 区域间距 | 20px，窄窗口 12–16px |
| 视频信息栏 | 默认 320px，可在 292–344px 内调整 |
| 编辑区 | `minmax(0, 1fr)`；优先获得剩余宽度 |
| 内容最大宽度 | 主内容容器约 1720px，不包含导航；超宽屏允许合理留白 |
| 来源输入 | 默认 44–52px 高；完整分享文本可展开至约 88–120px |
| 卡片 | 12–16px 圆角；内部间距 16–24px |
| 常用按钮 | 40–44px 高；窄布局图标按钮建议至少 36×36px |
| 文案正文 | 16px，行高约 1.75–1.9；不要照图用过小灰字 |
| 正文行宽 | 使用软换行，超宽编辑区内部正文约不超过 86ch；可据实际字体微调 |

### 4.2 响应式规则

| 扩展页面可用宽度 | 结构 |
|---|---|
| ≥1280 | 184px 导航＋约 320px 视频栏＋编辑区 |
| 1024–1279 | 导航收至约 64px 图标栏，视频栏约 288px，主编辑区优先 |
| 768–1023 | 导航改顶端菜单或抽屉；视频信息改紧凑横卡/可折叠区；编辑器占整行 |
| <768 | 单栏；链接区、紧凑视频卡、任务状态、编辑器纵向组织 |
| 320–480 的侧栏/弹窗 | 单栏紧凑形态；导航收起；导出按钮可换行或进入菜单；无横向页面滚动 |

断点依据当前扩展文档的实际可用宽度，不是显示器全屏宽度。侧栏虽然出现在大显示器上，其内部仍按窄模式处理。

若现有项目根本没有某种宿主入口，本轮不为凑齐表格新增该宿主。测试与交付需注明实际支持的入口。

### 4.3 滚动策略

宽屏模式：应用壳占可用视口，顶栏/来源栏与编辑区工具条保持可见；编辑器自身滚动；视频栏过高时独立滚动。关键 Grid/Flex 子项设置 `min-width: 0`、`min-height: 0`，避免长链接和正文撑破列宽。

窄屏及短窗口：允许页面纵向滚动，不能为了固定布局把控件裁掉。不要同时为卡片、卡片内层、编辑区、正文制造四层滚动条。工具条若使用 sticky，要与滚动容器匹配，并保证键盘焦点不会被遮挡。

每次切换主题、标签、布局断点时，文案内容、选择范围、光标、撤销栈和滚动位置尽量保持；不能通过卸载整个编辑器来换色。

## 5. ClipQuill 品牌与图标交付

### 5.1 造型要求

以第二张图的蓝紫羽毛笔为唯一图标参考：右上倾斜羽毛是视觉主体，左侧保留简洁视频/播放轮廓与小播放三角形，整体轻盈、有方向感。大图保留少量羽片切口；小图允许减去细节，但不能变成另一个标志。

不加入「抖」字，不出现 FrameWeave 名称；图标内不放英文缩写、小字、复杂纹理或不可辨识的描边。不要从海报截图直接裁出一块当最终资源，应重新绘制可维护的 SVG 路径。

### 5.2 主色与小尺寸策略

Logo 品牌渐变：`#4F8CFF → #8B5CF6`。页面交互采用第 6 节的可读性颜色，不要求所有按钮使用这组较亮渐变。

建议保留两种同源资产：透明背景符号用于页内 Logo；深色中性圆角底板版本用于需要稳定背景的扩展图标。favicon 可采用透明简化版。最终选用哪一种以真实浅/深浏览器背景测试为准，不依赖插件页面主题改变 Chrome 工具栏的颜色。

16px/32px 图标要单独优化：加粗关键轮廓、减少羽片细缝、给播放三角形留足负空间；必须在 100% 实际尺寸下查看，不只检查放大预览。

### 5.3 必需资源

目录名称可映射到现有项目，但交付物不得缺失：

```text
assets/brand/
  clipquill-logo.svg              # 图形主体矢量源
  clipquill-logo-small.svg        # 小尺寸简化母版（需要时）
  clipquill-wordmark.svg          # 可选；也可用普通文本呈现字标
icons/
  icon16.png
  icon32.png
  icon48.png
  icon128.png
  favicon16.png
  favicon32.png
scripts/
  <可复现的图标导出脚本或明确导出说明>
```

扩展 manifest 声明的图标使用 PNG，不将 SVG 直接填入这些配置；SVG 保留为设计源和适当的页内资产。Chrome 官方图标说明列出了 16/32/48/128 尺寸，且 manifest 图标不支持 SVG。[^chrome-icons]

如现有 action 图标需要额外 DPI 尺寸，可补 24/64 等，先保留现有配置兼容性，不依赖单个大图自动缩放。工具栏图标与提示文字由 action 配置/API 管理。[^chrome-action]

### 5.4 品牌配置修改

下列只是待合并字段的示意，**不是完整 manifest**：

```json
{
  "name": "ClipQuill",
  "short_name": "ClipQuill",
  "icons": {
    "16": "icons/icon16.png",
    "32": "icons/icon32.png",
    "48": "icons/icon48.png",
    "128": "icons/icon128.png"
  },
  "action": {
    "default_title": "ClipQuill",
    "default_icon": {
      "16": "icons/icon16.png",
      "32": "icons/icon32.png"
    }
  }
}
```

合并时保留已有 `manifest_version`、`version`、权限、`background`、`content_scripts`、`action.default_popup`、`side_panel` 等配置。不以此片段覆盖整个文件；不改扩展 ID 相关配置，不生成新 key，不随意重置版本。

有 `_locales` 与 `__MSG_...__` 时更新相应消息文件，不破坏国际化。检查运行时 `setTitle`、动态 `document.title` 或 `setIcon` 是否会把旧名称/旧图标写回。

主页面 `<title>` 使用 `ClipQuill`，真实设置页可采用 `ClipQuill · 设置`。description 如需更新，只陈述现有可用范围，例如「保存抖音视频，提取、编辑与导出文案。语音识别使用配套本地服务。」

### 5.5 浏览器原生区域的边界

Chrome 标签页形状、关闭按钮、侧栏原生头部、固定/菜单控件和浏览器外壳不是本扩展页面的 DOM。本任务仅配置扩展名称、图标、标题和页面内容，不试图通过 CSS 重画或控制原生外壳；侧栏能力以实际 `sidePanel` API 为边界。[^chrome-sidepanel]

参考图的浏览器效果仅作品牌预览。不要给扩展内容加假的 macOS 红黄绿按钮，不要修改用户打开的抖音网页标题来伪装成 ClipQuill，也不要把未激活标签自动变灰当作业务要求。服务离线使用状态提示，不切换成“坏掉”的灰色品牌标志。

### 6.1 视觉方向

**深色：** 接近参考图的石墨蓝黑背景；卡片轻微分层；蓝紫用于选中、主要行动和焦点；避免大面积发光、玻璃模糊和强渐变。

## 7. 主题切换的行为与实现规则

### 7.1 用户体验

顶栏提供一个有明确标签的主题菜单：`浅色 / 深色 / 跟随系统`。图标可以辅助，但不能仅给一个无说明的月亮让用户猜下一次会切到什么。

首次进入默认跟随系统。手动选浅色/深色后优先采用明确选择；再切回系统模式才重新响应系统变化。使用 `prefers-color-scheme` 获取系统/浏览器偏好，并以 `color-scheme` 告知原生表单等元素所用配色。[^mdn-theme][^mdn-color-scheme]

### 7.2 状态设计

```text
偏好值 themePreference：light | dark | system
实际值 resolvedTheme：light | dark

resolvedTheme = themePreference 为 system
  ? 当前系统配色
  : themePreference
```

建议在根节点区分偏好与实际主题，例如 `data-theme-preference="system"`、`data-theme="dark"`。页面颜色全部从语义变量读取；组件内部不散落 `isDark ? ... : ...` 硬编码。

### 7.3 持久化与跨页面同步

先复用现有设置系统。没有主题设置时，新建一个明确命名的键，如 `clipquill.ui.theme.v1`，存入 `chrome.storage.local`；不要触碰文案旧键，也不要调用 `storage.clear()`。

同扩展其他页面通过存储变更监听同步偏好。只处理主题键，避免监听器循环写入；在卸载时清理监听。Chrome Storage 支持相应存储与变更事件。[^chrome-storage]

系统模式下才监听系统配色变化。手动模式不被系统事件覆盖。存储读取较慢或失败时仍应可操作：先采用安全默认值，显示保存失败提示，不把按钮成功反馈当成已持久化。

若项目已使用页面级同步缓存减少闪烁，可仅缓存主题枚举；最终仍以统一设置存储为准。不要借此把文案、令牌或大文件迁移到 localStorage，也不要在 Service Worker 里调用页面专用 API。

### 7.4 首屏防闪与 CSP

尽早加载扩展包内的主题初始化脚本与基础主题 CSS，再展示完整应用内容。优先在挂载编辑器前解析主题；异步存储未完成时使用匹配默认主题的轻量背景，不长期隐藏应用。

**不得使用内联 `<script>`、`onclick` 或运行时 CDN 脚本来偷懒完成主题初始化。** 保持扩展现有 CSP，不为 UI 放宽安全策略；扩展页面的 CSP 对脚本来源和内联执行有明确限制。[^chrome-csp]

切换主题只改样式变量与必要状态，不刷新页面、不重新发起识别、不销毁播放器/编辑器、不改文案。需要处理初始化读取和用户快速切换之间的竞态，迟到的旧偏好不能覆盖新选择。

### 7.5 主题验收

以下必须分别验证：首次系统浅色/深色；明确选浅色后刷新；明确选深色后重开；两个扩展页面同步；系统模式实时响应系统变化；手动模式保持不变；编辑中切换不丢字；菜单/模态框/提示框与背景一起切换；存储异常可解释且可继续使用。

## 8. 输入、视频信息与任务状态

### 8.1 输入来源

保留当前“可粘贴整段抖音分享内容”的能力，不能改成只接受干净 URL。初始占位符写「粘贴抖音分享内容或视频链接」，不要照图写支持尚未实现的平台。

粘贴后调用已有解析/校验逻辑；无有效链接给出明确提示；多个候选链接时让用户选择或给出明确错误，不悄悄处理错误对象。长内容可展开查看，不能因一行输入截断用户原文。

默认顶部「获取作品」负责确认来源并使用现有能力获取元数据，**不隐式触发转写**。如果仓库没有独立元数据接口，可以只完成本地解析与来源确认，显示「已选择链接，视频信息将在处理时获取」，不得新增假接口或伪造“信息已获取”。若保留原交互更安全，可去掉此额外按钮，继续由「下载视频/提取文案」触发现有流程，并在阶段报告说明。

### 8.2 “已打开作品”与当前标签上下文

优先复用现有“选择已打开作品”。宽屏完整扩展标签页可能本身就是当前活动标签，不能把 `chrome-extension://...` 当作视频来源。可采用现有捕获的来源 tabId 或让用户从受支持页面中明确选择。

侧栏内的来源也要验证窗口和页面上下文。不要为了获取所有标签地址而自动新增过宽权限；`activeTab` 的授权与触发方式需要依据真实交互判断，不能假设扩展页面内任意按钮点击都会自动获得所有网页权限。[^chrome-activetab][^chrome-permissions]

只有一个受支持来源时可直接选择；多个时显示标题和平台供选择；没有时提示「请先打开一个支持的作品页面，或粘贴分享链接」。

### 8.3 视频卡片

展示真实封面、标题、作者、平台、时长、分辨率和文件大小。缺失字段隐藏或写「暂未获取」，不填示例数值。标题最多两三行，完整内容可展开；ID、缓存命中、文件路径等放“详细信息”。

有真实可播放资源时才显示播放按钮。封面本身不等于视频可播放；本地文件路径不直接伪装成浏览器可用 URL，沿用已验证的媒体访问方式。

下载与提取文案保持独立：下载不等于必须转写；提取文案内部可复用已有完整视频，必要时按现有流程获取文件，但不强迫用户先手动点击“下载视频”。主要按钮突出提取文案，下载为次要操作；处理中禁用会导致重复提交的操作。

### 8.4 按能力显示阶段

前端可以把实际后端状态映射为以下概念，但不能要求后端凭空提供全部状态：

```text
未选择来源 → 来源已确认 → 解析/获取 → 下载 → 提取音频
→ 语音识别 → 字幕对齐（若有）→ 模型校对（若有）→ 完成
                                        ↘ 失败/中断/状态未知
```

下载任务与文案任务分开判定完成。视频已下载但尚未转写时，右侧不能显示“文案已完成”。

有真实进度值才显示百分比；只有阶段信息时用阶段标签和不确定进度条。耗时从真实起止时间计算；不复刻参考图中的 2.1s、47.8s 等数字，不用假计时器把进度推到 99%。跳过/复用的步骤标记「已复用」而非虚构执行耗时。

### 8.5 错误与长任务

| 场景 | 用户应看到 | 保留/恢复规则 |
|---|---|---|
| 服务未连接 | 本地服务未连接＋重试连接＋现有启动帮助 | 不清空已有文案；只阻止真正依赖服务的操作 |
| 链接无效/平台不支持 | 输入附近明确说明 | 不发起下载或识别 |
| 下载失败 | 失败阶段、可操作建议、展开详情 | 保留输入与已取得元数据 |
| 识别失败 | 明确停在哪一步；真实可用的重试入口 | 保留可复用视频和旧稿 |
| 轮询失败 | 连接异常/状态待确认 | 不立即断言后端任务失败或成功 |
| 导出失败 | 导出类型与错误，允许重试 | 保留编辑稿 |
| 页面重开 | 恢复可确认的真实任务/草稿 | 无恢复机制时如实说明，不新增假“后台继续”能力 |

取消按钮仅在后端支持真正取消时出现；中止轮询不等于取消计算。重试需复用现有幂等/任务策略，不因 UI 重渲染重复创建任务。

保留任务 ID 与当前视频/文案版本的关联。A 视频的延迟响应不能覆盖用户已切换到的 B 视频文案。未经验证，不承诺关闭页面后下载/识别一定继续；原先要求保持页面打开的提示在得到实测证据前必须保留。

## 9. 文案编辑、字幕与导出

### 9.1 主编辑器

默认视图为纯文案编辑，保留换行和中文输入体验。沿用现有 textarea/编辑器组件；不为外观强行引入富文本编辑器或复杂虚拟化方案。

不要把参考图中的 `[00:00]` 文本直接拼进纯正文；不要硬编码 `482 / 10,000`，没有真实限制就只显示实际字数或省略计数。长文案不因 UI 重构被截断。

输入时不整页重渲染，不打断中文输入法 composition，不重置选区或撤销历史。复制、导出读取**当前编辑稿**，不是最初的 ASR 原文，也不是可能尚未写入磁盘的过期快照。

### 9.2 保存状态与覆盖保护

沿用已有草稿自动保存；如只有手动保存/最后一稿持久化，先如实呈现，不凭视觉直接宣称全量历史已自动保存。新增必要的 UI 防抖和保存指示可在不改变旧格式的前提下实施。

状态至少区分「有未保存修改 / 保存中 / 已保存 / 保存失败」。只有实际持久化成功后才写“已保存”；显示的保存时间来自成功结果。

建议防抖约 500–800ms，并处理异步写入顺序。恢复旧稿、切换作品或重新提取可能覆盖当前编辑内容时，先确认或保存安全副本；不能自动覆写用户手工修改。页面关闭只做尽力保存，不宣称生命周期最后一刻的异步写入必然成功。

### 9.3 字幕列表与回听校对

参考图里的“字幕时间轴”在本轮优先实现为**已有字幕段列表视图**，而不是新建可拖动剪辑时间轴。已有回听/模型比对能力则迁移到相应标签或抽屉；没有时间戳或播放器能力则隐藏相关操作，并说明条件。

字幕时间与文案分离展示。点击真实段落可按已有媒体方式定位；时间戳不作为普通文本随意编辑。没有真实模型差异或置信度数据时不伪造高亮与分数。

切换正文、字幕、回听视图必须使用一致的数据来源，不形成三个互相覆盖的独立草稿。

### 9.4 SRT 语义是本轮重点保护项

用户原界面明确说明：SRT 沿用原字幕时间；跨段修改会合并原时间区间；新增文字归入所在区间；不重新估算时间。**先找到实际实现并用 fixture 固定其行为，再迁移界面。**

必须保留原始识别结果与当前编辑稿之间的映射信息；不能简单按新稿换行数平均分配视频时长，也不能只导出旧字幕而忽略新稿。

测试至少覆盖：单字替换；新增/删除文字；跨段粘贴；合并两段；连续换行；全部清空；中英文/标点；同一稿编辑后 TXT 与 SRT 文本一致性。存在无法可靠映射的编辑时应明确警告或按既有安全规则处理，不能静默生成看似精准的错误时间戳。

SRT 格式、段号、非负起止时间、起点早于终点和时间顺序须验证；有效数据中的时间不能无故超出视频时长。本轮不得借“优化 UI”重写对齐算法。

### 9.5 固定导出工具条

工具条放编辑器可见区域，不要求用户滚到底部。常用项：复制全文、导出 TXT、导出 SRT；其他操作进入溢出菜单。窄屏可换行或菜单收纳，但不能出现页面横向滚动。

复制仅在写入成功后提示成功；失败时提供手动复制路径。导出提交给浏览器成功时显示「已发起导出」，只有确知下载完成才显示「已保存文件」。不要把下载 API 调用成功等同于用户已找到磁盘文件。

TXT 使用现有兼容编码与命名规则；SRT 保持原规则；如生成下载文件名，处理非法字符和过长名称。导出临时 Blob/Object URL 按既有方式正确释放。

清空属于危险操作，进入更多菜单或清晰区分的按钮；有内容时确认，且不得顺带删除历史文案、缓存视频或整个存储。恢复、复制和导出后的提示采用状态区或 toast，不叠加一长串常驻成功横幅。

## 10. 历史/最近稿、高级选项与设置

### 10.1 历史功能不扩张

若已有可用多任务历史数据，显示真实历史列表和恢复入口；没有则不要新造历史管理数据库来补齐导航。只有“恢复上次文案”时，将入口命名为「最近文案」或继续保留“恢复上次文案”，最多展示真实存在的一条记录。

图片中的“历史记录”是布局参考，不是必须虚构多条历史任务的需求。选择历史时保护当前未保存稿；无历史显示空态，不填演示内容。删除记录功能仅在现有能力与安全边界清楚时迁移。

### 10.2 高级选项

把现有辅助参数迁移至可展开区域或设置抽屉，不改其默认值、含义和后端字段。术语提示、模型校对等任务参数需要在提交任务前明确生效；处理中禁用会误导用户的修改，或说明仅影响下一次任务。

一般设置与单次任务参数分开，不把“保存目录”“术语提示”“主题”堆在一个无层次的长表单里。高级功能可收起，但不得直接隐藏掉用户原本能够使用的能力。

### 10.3 设置与诊断

保留实际可用项：主题偏好、本地服务连接信息/帮助、现有默认参数、保存与恢复说明、版本与必要诊断。版本号从项目实际信息读取，不固定为参考图中的 `v1.0.0`。

错误详情可折叠显示；用户可复制脱敏诊断。日志不包含 Cookies、令牌、完整私密文案或不必要的绝对个人路径。不增加云端分析或遥测。

## 11. 推荐的前端组织方式

沿用现有技术栈；下列是职责划分，不是强制目录或框架：

```text
AppShell                导航、顶栏、布局断点
ThemeController         偏好读取、系统解析、跨页同步
SourceInput             分享内容与来源选择
VideoSummary            视频元数据、封面/可用播放器
TaskActions             下载/提取入口、防重复提交
TaskProgress            真实阶段、错误、详情
TranscriptWorkspace     当前稿与视图切换
TranscriptEditor        编辑、输入法、选择、撤销
ExportActions           复制/TXT/SRT，读取当前编辑稿
RecentDrafts            已有恢复/历史能力
AdvancedOptions         现有任务参数
ServiceStatus           真实服务状态和重试
```

对原生 HTML/CSS/JS 项目，这些可以是小模块和 DOM 区域，不要求重写成组件框架。以最少结构变更实现可维护边界。

若旧 JS 依赖元素 ID、data 属性或事件委托，移动节点时保持这些契约；重命名则一次性更新所有引用并测试。避免把原页面复制成另一个仅静态美观的新页面，再让默认入口仍指向旧 UI。

### 11.1 薄适配层

仅在有必要时把既有响应转换为 UI 需要的视图数据。底层契约不变，UI 不直接操作模型或重新实现下载流程。概念数据包括：当前来源、当前视频、任务 ID 与阶段、连接状态、原始字幕、当前编辑稿、保存状态、主题偏好。

后端返回未知状态时保留原值用于诊断，并以“处理中/状态待确认”安全展示；不要把未知值默认映射到成功。

### 11.2 安全与工程限制

- 标题、作者、分享内容、字幕均当作不可信文本，使用文本节点或等价安全方式渲染，避免原样写入 `innerHTML`。
- 复用现有权限和通信机制；UI 改动不能成为添加 `<all_urls>`、扩大本地文件访问或关闭 CSP 的理由。[^chrome-permissions][^chrome-csp]
- 图标、脚本和需要的样式随扩展打包；不为展示图拉取陌生 CDN 脚本，不新增非必要网络字体和统计服务。
- 所有请求处理失败、重复点击和组件销毁；主题/布局变化不能创建额外的轮询器或识别任务。
- 不把 MP4、音频等大文件塞进主题/设置存储；不在浏览器端重新实现本机文件系统服务。
- 只给必要 UI 添加依赖；复用锁文件和包管理器，不做与任务无关的升级或全库格式化。

## 12. 分阶段执行计划与检查点

### 执行规则

每个阶段先小范围实现，再跑对应验证，最后记录“改了什么、验证了什么、哪些未验证”。如果某项需要重构底层、增加权限或迁移用户数据，先停在该分支上报告，不把它夹带到 UI 提交。

正常的小改动无需每一步询问；第一次视觉检查点在 **S3 完成后**。建议第一轮执行 S0–S3，用户确认方向后再完成 S4–S6。任何中间阶段都不应把默认入口替换成失去已有功能的假页面。

### S0 · 仓库审计、功能基线与风险冻结

**目标：** 知道要改哪一层，以及哪些契约不能动。

| 任务 | 产出 |
|---|---|
| 读规则、入口、配置，查看工作区已有改动 | 实际入口与技术栈清单 |
| 盘点下载/转写/保存/导出/回听/历史 | 带证据等级的能力矩阵 |
| 记录旧页面深度、操作流程与数据行为 | 基线截图/运行记录 |
| 运行已有测试及最小业务检查 | 通过项、已有失败、环境阻塞 |
| 对照参考图识别非真实功能 | 删除/隐藏/沿用的决策记录 |

**验收：** 有 `baseline.md`；明确完整页和窄入口；找到 SRT 映射与草稿存储；不改用户数据。若无法确定当前文案如何保存，先完成调查，不贸然搬动编辑器。

### S1 · 品牌资产与浏览器展示统一

**目标：** 先消除「抖」字占位图和旧产品名，建立统一标识。

| 任务 | 产出 |
|---|---|
| 按第二张图重绘 Logo，大/小尺寸优化 | SVG 源与 PNG 多尺寸 |
| 更新 manifest、国际化、标题与 favicon | 正式名称统一为 ClipQuill |
| 排查运行时旧图标/旧标题写回 | 不会打开后变回旧品牌 |
| 真浏览器检查浅/深工具栏和标签显示 | 图标实际尺寸截图 |

**验收：** 扩展加载无图标报错；16px 能辨识；已有入口、权限、版本和业务不受影响。名称替换只改用户可见品牌，不全库替换底层 storage key/协议路径。

### S2 · 双主题基础与通用组件

**目标：** 先做完整可切换主题，再把新布局建立在同一组样式变量上。

| 任务 | 产出 |
|---|---|
| 建立第 6 节语义 Tokens | 统一深浅主题样式 |
| 实现主题偏好、系统解析、持久化和同步 | ThemeController 或等价实现 |
| 统一按钮、卡片、输入、标签、菜单、提示 | 两主题同等覆盖 |
| 处理首屏初始化、CSP、焦点与减少动画 | 无内联脚本取巧、无明显闪白 |

**验收：** 三种偏好行为正确；切换不改文案；重开保留选择；现有页面在两主题下仍可用。错误/菜单等非主画面也必须检查。

### S3 · 新布局与响应式迁移（第一次视觉检查点）

**目标：** 在真实扩展入口中获得接近参考图的空间组织，而非独立演示页。

| 任务 | 产出 |
|---|---|
| 实现 AppShell、来源栏、视频栏、编辑区 | 宽屏三块横向布局 |
| 迁移原有节点或组件并保留事件连接 | 原操作入口继续工作 |
| 固定/就近放置编辑导出工具条 | 不必滚动长页面才能复制 |
| 适配折叠导航、窄屏和短窗口 | 320–1920 宽度范围内按规则降级 |
| 去掉重复设置、假窗口控件、无用宣传 | 聚焦插件处理任务 |

**验收：** 至少提供 1440×900 深浅各一张真实页面截图，以及 1024×768、窄入口约 390×844 的布局截图。基础编辑/下载/提取/导出仍能从新位置调用原功能。主题切换不会重建编辑器。

**停点：** 记录视觉差异、未验证真实流程与后续事项，请用户确认蓝紫品牌、羽毛笔图标、布局和浅色风格。不要在此声称 S4–S6 已完成。

### S4 · 输入与真实任务状态整合

**目标：** 让新布局中的视频信息、操作和状态真实可靠。

| 任务 | 产出 |
|---|---|
| 复用分享链接解析与已打开作品逻辑 | 正确来源选择，不抓到插件自身 |
| 绑定真实视频数据与可播放资源 | 无硬编码示例作品 |
| 整合下载/提取/复用行为 | 无重复任务、无强制手动前置下载 |
| 映射阶段、重试、连接异常与恢复 | 不伪造百分比/取消/完成状态 |
| 处理并发响应与组件生命周期 | A 任务不能覆盖 B 任务 |

**验收：** 服务在线/离线均可用；有效/无效链接与多来源可解释；已下载视频能按现有规则复用；完成/失败/未知状态准确；页面重开行为与底层能力一致。

### S5 · 文案、字幕、回听与恢复迁移

**目标：** 外观改变不损失任何用户编辑与导出语义。

| 任务 | 产出 |
|---|---|
| 接入当前稿、保存状态、防覆盖逻辑 | 切视图/换主题不丢内容 |
| 迁移复制、TXT、SRT 操作 | 导出的是当前稿 |
| 回归原字幕映射规则 | 通过跨段编辑与新增文字测试 |
| 迁移已有字幕/回听/双模型视图 | 不伪造时间戳和模型数据 |
| 处理最近文案/真实历史与高级参数 | 保留旧入口能力，避免功能膨胀 |

**验收：** 中文输入法、撤销/重做、长文案、自动保存失败、恢复旧稿、TXT/SRT 一致性全部验证。SRT 未通过回归不得标记本阶段完成。

### S6 · 全量回归、视觉精修与交接

**目标：** 交付可继续维护、可验证、可回退的新界面。

| 任务 | 产出 |
|---|---|
| 执行第 13 节测试矩阵 | 逐项结果与证据 |
| 真扩展环境测试，不只本地网页预览 | CSP、权限、消息与媒体路径检查 |
| 深浅主题、小图标、键盘、缩放精修 | 最终截图与可访问性记录 |
| 清理开发 fixture、重复 CSS、死代码 | 无演示数据混入生产 |
| 审核 Git diff 与改动边界 | 无意外后端/权限/数据迁移 |
| 写运行、测试、差异和回退说明 | 最终交接文档 |

**验收：** 符合第 14 节完成定义；未通过项明确列出，不把“缺少环境未测”当作通过。不自动发布、推送或升级生产版本。

### 13.4 可访问性与交互

文本遵循 WCAG AA 的相应对比要求：常规文字至少 4.5:1，大号文字至少 3:1；必要的非文本 UI 视觉信息也要检查 3:1 对比度。[^wcag-contrast][^wcag-nontext]

Tab 能到达所有操作；焦点清晰、不被 sticky 工具条遮挡；菜单可 Esc 关闭并返回触发按钮；模态框正确管理焦点；表单有标签；状态消息适度使用可读通知而不连续打断读屏；不能只靠红绿区分成功与失败。

本项目把常用图标按钮目标设为 36×36px 以上，主要操作约 40–44px 高；同时检查 WCAG 2.2 的 24×24 CSS px 最小目标及其适用例外。不要将本项目建议的 44px 误写为所有控件的 WCAG AA 强制阈值。[^wcag-target]

验证 200% 缩放和可重排内容；窄入口至少检查 320 CSS px 等效宽度。若操作系统滚动条与表单样式不同，以可访问和可操作为先，不强行追求截图像素完全一致。

### 13.5 真实环境与报告

复用现有测试工具；有浏览器自动化能力则添加主题解析、状态映射、源链接处理、旧数据兼容和导出回归测试。安装新测试框架前先说明必要性，不强制引入重型工具。

普通网页预览和纯 DOM 测试不能替代真实扩展环境中的权限、CSP、消息、存储与本地服务测试。报告分开写：静态检查、单元/fixture 测试、扩展端到端、人工视觉检查、尚未验证。

截图文件建议命名如 `main-dark-1440x900-complete.png`、`main-light-1440x900-complete.png`、`narrow-light-390x844.png`。报告记录实际 CSS 视口和 DPR；不得把 AI 生成参考图当作实现截图交差。

### 14.1 全部满足才可声称完成

- [ ] 文案保存、恢复、复制、TXT/SRT 和既有回听通过相应回归。

### 14.2 回退策略

每阶段保持可审查的独立 diff；遵循用户现有 Git 工作流，不把无关修改混进提交。必要时使用独立分支或可关闭的新 UI 开关，但不永久维护两个互相分叉的产品页面。

出现阻断性回归时，只回退本轮相关 UI/适配修改，保留用户已有工作。避免破坏性数据迁移；新增主题键即使旧版本忽略也不影响原文案。文案数据格式确需改动时必须先提出独立方案并获得确认，不能作为本计划默认授权。
