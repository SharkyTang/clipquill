# ClipQuill：Codex 新对话提示词

**使用方式：** 把整个 `ClipQuill_UI_Handoff_2026-10-14` 文件夹放进 ClipQuill 现有仓库中，保留 `references/` 与两份 Markdown 的相对位置。在该仓库开启 Codex 对话后，复制下面「首轮提示词」代码块的全部内容。若通过附件提供材料，同时附上两张参考图，不要只发送这段提示词而遗漏规划。

本文件不用于修改 FrameWeave 映构，也不要求创建新仓库或替换现有 `AGENTS.md`。

## 首轮提示词：审计＋品牌＋双主题＋布局

```text
请在当前 ClipQuill 仓库中直接执行一次增量 UI 重构。先阅读项目已有的 AGENTS.md、README、manifest、入口代码和工作区改动，再阅读我提供的完整交接文件及两张参考图。

交接文件夹：ClipQuill_UI_Handoff_2026-10-14
主要文件：
- ClipQuill_Codex_执行规划.md
- references/01-layout-reference.png
- references/02-brand-icon-reference.png

如果材料放在 docs 等子目录，先在当前仓库定位这些文件，不要虚构文件内容。若确实无法访问参考图或执行规划，先指出缺少的材料，不要另猜一套视觉方案。

【产品边界】
ClipQuill 是浏览器扩展，负责视频获取/下载、文案提取、本地语音识别以及编辑、校对和导出。FrameWeave 映构是另一个私人桌面工作台，不在这次范围内。不要把 ClipQuill 变成桌面 App，不要创建 Electron/Tauri 项目，不要新增 AI 视频分析、创作知识库、热点发现、账号付费或 FrameWeave 接入功能。

【参考图优先级】
第一张图只负责页面结构：紧凑左导航、顶部来源输入、中间视频信息与操作栏、右侧大文案编辑区。
第二张图负责品牌：蓝紫渐变羽毛笔＋播放符号，名称 ClipQuill。
最终采用“第一张布局＋第二张 Logo＋统一蓝紫品牌＋深浅主题”。不要保留第一张的青绿色 C 形图标，不要把绿色作为主品牌色；绿色仅用于连接正常、成功等状态。
不要照搬图片里的假窗口红黄绿按钮、示例视频、硬编码进度/耗时、10,000 字上限或未实现平台宣传。不要为了填满侧栏增加不存在的历史任务和产品模块。

【主题要求】
必须支持浅色、深色，并补充跟随系统；首次默认跟随系统。用户手动选择优先，偏好持久化，已打开的扩展页面同步。主题覆盖页面、导航、卡片、输入框、编辑器、菜单、弹窗、toast、焦点与错误态，不能只换背景色。
采用执行规划的语义颜色变量。初始化与存储逻辑要兼容现有扩展 CSP，不使用内联脚本或 CDN 脚本取巧。切换不能刷新页面、重新创建任务、丢失文案/光标或破坏撤销记录；需要避免明显闪白。

【先保护既有能力】
先确认实际技术栈和宿主入口：完整扩展标签页、side panel、popup、options 哪些真实存在。沿用当前框架与构建方式，不引入无必要的框架迁移。
盘点并保持链接解析、下载、文件复用、音频处理、识别、字幕对齐、现有模型校对、回听、编辑、草稿恢复、TXT/SRT 导出等已存在能力。
不改本地服务端口、下载路径策略、模型、底层算法、消息协议和已有 storage key；不清数据、不更换扩展身份、不顺便升级依赖。不要覆盖未提交的用户改动，不执行破坏性 Git 清理，不自动发布或推送。
如果旧 JS 依赖 DOM ID/事件委托，移动界面时保留或完整迁移引用。新 UI 必须进入真实扩展入口，而非另起一个没有功能的静态 demo。

【特别注意】
1. 先审计，区分已验证、有实现未验证、仅 UI、缺失、环境阻塞；图片不是功能证明。
2. 只展示已支持平台；有完整历史才叫历史记录，只有上一稿则保留最近文案/恢复上次文案。
3. “已打开作品”不能错误抓到 ClipQuill 自己的扩展标签。复用实际来源选择与权限方式，不擅自扩大网页权限。
4. 视频下载和文案提取独立；提取时可按已有规则复用视频，不强迫手动先下载。
5. 不伪造进度、成功、保存时间、模型分数或取消能力；后台没有百分比就只显示实际阶段。
6. 文案编辑保护中文输入法、光标、撤销与当前稿。复制/TXT/SRT 必须使用当前编辑稿。
7. SRT 的现有时间映射规则必须回归：沿用原时间，跨段编辑按现有规则合并时间区间，新增文字按现有规则归属，不平均重估时间。
8. 蓝紫羽毛笔需重绘 SVG 源并导出 PNG；不要裁海报当正式图标。检查 16/32/48/128px，以及 favicon 和运行时标题。manifest 图标使用 PNG，不直接填 SVG。
9. Chrome 原生标签、关闭按钮、侧栏头部/固定/菜单不是插件页面可随意重画的控件。本次只改自己的图标、名称、标题和页面，不修改抖音网页或 Chrome 主题。
10. 窄入口使用单栏/折叠，不在 390px 的侧栏里硬塞三栏；宽屏编辑/导出常用操作保持可见。

【这次执行到哪里】
按完整执行规划依次完成 S0、S1、S2、S3：
S0：仓库审计、能力矩阵、原行为与可运行测试基线。
S1：羽毛笔品牌资产、ClipQuill 命名、manifest/标题/favicon 统一。
S2：双主题变量、切换/持久化/系统模式、通用组件样式。
S3：真实入口的新布局与响应式迁移，保留现有事件和可用业务入口。

不要只给方案然后停止；完成必要审计后直接实施这四个阶段。正常的小改动无需逐次询问，但涉及底层重写、数据迁移、权限扩大或其他越界事项时先报告，不擅自处理。

S3 完成后作为第一次视觉检查点暂停，不自动进入 S4–S6。提供实际实现截图：1440×900 深色和浅色各一张，1024×768 至少一张，存在窄入口时再给约 390×844 的截图。截图必须来自运行中的实现，不拿参考图或假数据冒充真实处理结果。可以使用明确隔离的测试 fixture 检查视觉，但要标明测试数据，不能作为真实任务成功的证据。

【本轮汇报格式】
先简要说明发现的真实入口、技术栈、关键风险以及将改动的范围；继续实现。
完成时列出：改动文件及职责、实际运行的构建/测试与结果、原功能是否仍可用、截图路径、相对参考图的必要偏离、未验证项和 S4–S6 待办。
若不能运行浏览器/本地服务，明确说明不能验证的部分，不声称端到端通过；但继续完成可以验证的静态、单元和布局工作。
记录本阶段结果到项目文档，供下一次对话接续。不要自动发布、推送或覆盖用户已有工作。
```

## 视觉确认后的继续提示词：真实状态＋编辑导出＋回归

确认第一轮布局与深浅主题方向后，在同一仓库使用这一段；不必从头重做。

```text
继续 ClipQuill UI 重构。先阅读 ClipQuill_UI_Handoff_2026-10-14/ClipQuill_Codex_执行规划.md，以及上一轮的 baseline、implementation-log、实际代码差异和我最近的反馈。

沿用已确认的第一张布局＋第二张蓝紫羽毛笔 Logo，以及完整深浅主题；不要重新设计品牌或混入 FrameWeave 映构。核对 S0–S3 的实际完成状态，未完成的先补齐，不凭历史回答认定已通过。

本轮依次完成 S4–S6：
S4：绑定真实来源选择、视频元数据、独立下载/提取、文件复用、服务状态、进度/错误/恢复；防重复任务与迟到响应覆盖。
S5：迁移当前文案、持久化、复制/TXT/SRT、现有字幕/回听/模型校对、真实历史或最近文案、高级参数。严格回归现有 SRT 时间映射；不新建剪辑式时间轴或不存在的能力。
S6：执行规划的功能、主题、品牌、响应式、可访问性与真实扩展测试矩阵，精修并完成交接。

保留原技术栈、后端与用户数据。没有后台能力的按钮隐藏或解释原因，不伪造进度、成功和历史。所有导出使用当前编辑稿；切主题/视图不丢光标和内容；存储失败要如实提示。

实际运行可以运行的测试，并记录命令、结果、环境和阻塞。普通网页预览不能替代真实扩展的权限/CSP/消息/本地服务验证；无法运行真实服务时明确标为未验证，不写全部完成。

交付：最终深浅主题与窄入口真实截图、关键文件清单、测试矩阵结果、已知问题、原功能保留情况、查看和重载步骤、回退说明。不自动推送或发布，也不要处理与此次 UI 无关的重构。
```
