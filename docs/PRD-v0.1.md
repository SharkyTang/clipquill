# 开源视频插件与私人创作工作台第一版 PRD

版本：v0.1.1  
日期：2026 年 10 月 12 日  
状态：产品方案草案，尚未进入代码开发  
适用范围：面向 Windows 和 Mac 用户的 Edge 与 Chrome 开源插件，以及仅供产品所有者个人使用的创作工作台

开源插件帮助用户快速获取视频和文案；私人工作台把收集的素材转化为有来源依据的 AI 拆解，再结合个人创作背景生成可以实际拍摄的方案。第一版优先验证单条视频的完整流程。

推荐第一版采用 Edge 与 Chrome 共用主体代码的插件、本机网页工作台和本地后台服务。公开插件与转写配套支持 Windows x64、Apple Silicon Mac 和 Intel Mac；工作台在产品所有者的 Mac 上优先验收。所有新增兼容范围均为开发与验收目标，不是已完成支持的声明。

工作台在浏览器中打开，素材和任务记录由本机服务保存。私人工作台不作为公开插件的必需依赖。国内安装与首次模型准备不以访问 Google 服务、GitHub 或 Hugging Face 为唯一途径。本次仅更新产品文档，不修改现有代码、发布包或运行配置。

## 1 产品目标与用户

### 1.1 产品目标

1. 公开用户能独立下载视频、提取并导出文案，交给自己习惯的 AI 使用。
2. 产品所有者能从浏览器快速收集视频，不需要每条手动整理目录、输入标签或搬运文件。
3. 工作台能解释参考视频中值得借鉴的结构和表达方式，并给出对应来源位置。
4. 生成的创作方案符合个人受众、目标和拍摄条件，包含可执行的脚本、分镜与准备清单。

### 1.2 用户与使用目的

| 用户 | 目的 | 第一版体验 |
| --- | --- | --- |
| 公开插件用户 | 在 Windows 或 Mac 上临时保存视频或提取文案，交给外部 AI | 在 Edge 或 Chrome 安装插件即可下载；完成对应系统的本地转写服务一次性准备后可提取文案；不需要私人工作台账号 |
| 产品所有者 | 持续收集参考视频，拆解后形成自己的创作方案 | 连接私人工作台，一键收集，进入工作台分析和生成 |

第一版工作台是单人、单机使用。私人使用表示工作台源码、个人配置和内容均不随插件公开；它不等同于所有 AI 推理都必须在本地运行。

### 1.3 第一版不包含的内容

- 自动寻找或排名爆款，自动抓取账号全集，定时采集和批量下载。
- 多条视频联合分析、团队协作、多用户账户、付费和订阅。
- 视频自动生成、自动剪辑、自动发布，以及账号运营自动化。
- 整套移动端、独立桌面工作台、云同步和公网部署。
- 将逐句校对设为使用门槛，或承诺自动转写完全准确。
- 对所有作品、全部画质、所有浏览器和所有电脑作通用兼容承诺。

## 2 产品形态与平台选择

### 2.1 第一版推荐形态

| 部分 | 推荐形态 | 原因 |
| --- | --- | --- |
| 插件 | Edge 与 Chrome 浏览器扩展，轻量入口加结果工具页 | 共用主要业务与界面，分别验收浏览器权限、下载和配套服务连接；国内使用指引优先提供 Edge 路径 |
| 私人工作台 | 本机服务提供的网页，在浏览器中打开 | 便于快速迭代素材列表、视频播放、分析和方案页面，第一版无需额外维护桌面窗口和安装包 |
| 后台处理 | 独立于页面的本地服务 | 保存文件和任务，负责转写、抽帧和 AI 调用；页面关闭后，已接收的任务可以继续 |
| 存储 | 本机持久化目录与数据库 | 私人数据独立于插件源码、浏览器缓存和开发仓库 |

这里的网页工作台是由本机服务提供的应用，不是上传视频到公开网站。只做一个没有后台的网页，不能替代持久化文件管理和独立任务处理。

Chrome 下载 API 能发起并监控下载。Manifest V3 的扩展后台存在终止和休眠机制，因此长任务需要持久化记录，不能只依赖插件页面或后台内存。[Chrome 下载 API](https://developer.chrome.com/docs/extensions/reference/api/downloads)、[扩展后台生命周期](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)。

网页读取用户普通文件目录需要相应授权。第一版因此由本地服务管理应用素材目录，工作台通过受控接口访问这些素材，避免把任意磁盘路径当作网页可直接读取的资源。[File System API](https://developer.mozilla.org/en-US/docs/Web/API/File_System_API)。

### 2.2 网页与桌面工作台的取舍

| 方案 | 适合的需求 | 本项目第一版判断 |
| --- | --- | --- |
| 公网网页工作台 | 多设备访问和远程协作 | 暂缓，需要新增视频上传、远程存储、账户与访问控制 |
| 本机网页工作台加后台服务 | 单人使用、本地素材、尽快验证创作流程 | 优先采用 |
| 桌面工作台加浏览器插件 | 一键启动、托盘、系统通知、文件管理和安装体验 | 当这些体验成为主要使用障碍时再投入 |

桌面版仍然保留浏览器插件作为收集入口。后续可评估用 Tauri 或 Electron 承载工作台页面，但仍需重新验证安装、权限、后台生命周期和更新，不能把包装成桌面窗口视为完成交付。Tauri 支持使用网页技术构建应用界面，这支持后续复用界面的可能性。[Tauri 官方介绍](https://v2.tauri.app/start/)。

### 2.3 双浏览器与操作系统支持矩阵

公开插件与转写配套的第一版支持目标如下。阶段 0 固定最低操作系统版本、浏览器版本、CPU 要求、内存和可用磁盘空间，写入安装页与发布说明；不能用笼统的 Windows 或 Mac 名称承诺所有旧系统均可运行。

| 操作系统与硬件 | Edge | Chrome | 文案提取基线 | 当前项目验证情况 |
| --- | --- | --- | --- | --- |
| Windows x64 | 第一版正式验收 | 第一版正式验收 | whisper.cpp CPU，不要求独立显卡 | 两个浏览器及配套服务均待实测 |
| Apple Silicon Mac | 第一版正式验收 | 第一版正式验收 | whisper.cpp 基础路径；就绪时可采用 Qwen3 本地增强路径 | Chrome 的既有 Qwen3 路径有单样本记录，新增基础路径和 Edge 待验收 |
| Intel Mac | 第一版正式验收 | 第一版正式验收 | whisper.cpp CPU | 两个浏览器及配套服务均待实测 |

Windows ARM、Linux、Firefox、Safari、移动浏览器和其他 Chromium 浏览器不列入第一版正式支持。其他 Chromium 浏览器可以作为候选，按具体版本验证后再扩展说明，不能仅因同内核宣布兼容。

Edge 与 Chrome 共用页面识别、下载、结果和连接协议；商店元数据、扩展标识和权限差异分别处理。微软提供 Chrome 扩展迁移指南，但仍要求检查 API 并在 Edge 中测试，因此迁移可能性不等于本项目已经兼容。[Edge 迁移指南](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/port-chrome-extension)。

两个浏览器可连接同一用户的一套转写服务，通过任务身份关联结果。服务允许多个经过配对的扩展标识，不能只硬编码现有 Chrome 扩展 ID；也不能为了兼容而接受任意扩展来源。复制安装目录、重新加载或商店版本改变身份后，设置页提供重新连接方式，普通用户不需要输入或修改扩展 ID。

私人工作台第一版在产品所有者的 Mac 上通过 Edge 和 Chrome 验收。Windows 用户无需安装它；公开插件中的工作台连接协议另做同机兼容服务测试，不承诺 Windows 默认能访问另一台 Mac 的本机工作台，也不因此扩展到公网部署。

### 2.4 国内安装与更新渠道

| 路径 | 面向用户 | 第一版要求 |
| --- | --- | --- |
| Edge 扩展商店 | 普通用户优先路径 | 单独打包、提交并通过审核后提供商店入口；此渠道无需通过 Chrome 应用商店安装，不代表任意国内网络下都保证可达 |
| 国内下载页与开源 ZIP 发布包 | 无法访问商店的用户、开源用户和内测用户 | 提供与源码版本对应的 ZIP、图文安装说明、校验值和配套服务入口；下载渠道不只有 GitHub |
| Chrome 应用商店 | 能正常访问的 Chrome 用户 | 作为补充渠道，不作为国内使用的前置条件；发布和审核状态单独说明 |

ZIP 包需要先解压，Edge 在 `edge://extensions`、Chrome 在 `chrome://extensions` 开启开发者模式，选择加载解压后的扩展并选中含 `manifest.json` 的目录。安装页按两种浏览器和两类系统分别提供图文说明，不让用户猜测按钮或目录位置。此为手动安装路径，不承诺等同于商店的一键安装或自动更新。[Edge 本地加载说明](https://learn.microsoft.com/en-us/microsoft-edge/extensions/getting-started/extension-sideloading)、[Chrome 本地加载说明](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world)。

不把拖拽 CRX、修改注册表或企业策略写成普通 Windows 与 Mac 用户的通用安装方式；Chrome 的外部安装存在限制，手动加载解压目录与外部自动安装须区分。[Chrome 替代安装方式](https://developer.chrome.com/docs/extensions/how-to/distribute/install-extensions)。受单位管理且禁止安装扩展的设备显示不支持当前安装路径，不引导绕过管理策略。

配套服务提供 Windows x64、macOS arm64 和 macOS x64 三种发布包，准备所需运行环境与音视频处理组件。普通用户不必自行安装 Python、编译 C++ 或运行模型下载命令。安装器或启动器只服务于本地转写和连接，不新增一套桌面工作台界面。

模型通过项目维护的国内可访问下载入口准备，也支持导入离线模型包。发布前核对模型与组件的再分发条件，固定来源、版本与校验值，并实测国内下载；未实际部署的镜像和下载地址不能写成已可用。自动下载与离线导入均显示大小、进度、剩余磁盘要求、失败重试和完成状态。

商店版本按商店机制更新；手动 ZIP 版本提供清楚的下载、替换和重新加载步骤，不能承诺自动更新。更新配套服务和模型时保留已有文案、私人素材及连接设置，发生身份变化时引导重新连接。

### 2.5 文案提取兼容方案

第一版采用统一的本地转写服务接口，按电脑能力选择运行引擎。浏览器只提交任务、查询进度和展示结果，不承担大模型推理，不要求公开用户配置 AI API Key。

| 电脑类型 | 第一版方案 | 加速与增强边界 |
| --- | --- | --- |
| Windows x64 | whisper.cpp CPU 作为必需基础路径，优先评估现有 Whisper Turbo 量化模型 | GPU 加速为可选项，首发不要求 CUDA、独立显卡或用户手动选择驱动后端 |
| Intel Mac | whisper.cpp CPU 作为必需基础路径 | 按 CPU 环境实测速度和质量，不套用 Apple Silicon 的模型或速度结果 |
| Apple Silicon Mac | whisper.cpp 基础路径；现有 Qwen3 本地方案作为可选增强 | 能力和已安装模型满足条件时自动选择；GPU 加速单独验收，不把 MLX 设置为全部系统的依赖 |

whisper.cpp 官方列出 Windows、Intel Mac、Apple Silicon Mac 和 CPU 推理支持，因此可作为跨平台基础方案；这不意味着当前 Python 包装、安装方式或输出质量已经通过跨平台验证。[whisper.cpp 官方项目](https://github.com/ggml-org/whisper.cpp)。

工程适配必须包含各系统的音轨转换、中文和空格路径、下载目录定位、临时文件、启动停止、超时取消和重启恢复，不能把现有 Mac 脚本原样复制到 Windows 当作完成兼容。

统一输出正文、时间段、TXT、SRT 和任务状态，允许各引擎的具体识别文字不同，但都必须经过同一组中文、英文术语、数字、背景音乐与长停顿样本检查。Whisper Turbo 量化模型是基础模型候选，最终版本与最低硬件要求在阶段 0 的普通 CPU 设备测试后固定；性能不足或质量不过关时缩小实际支持说明，不能仅因模型能加载就通过验收。

面向普通用户的默认任务只运行所需的主识别，不额外强制第二模型对照或词级精校。SRT 可使用主引擎有效时间段；精细对齐和细致校对为辅助能力，不阻塞默认全文结果。已有 Qwen3 增强路径所需的对齐与依赖在配套服务内部处理，不把模型设置放到插件主界面。

首次准备时说明当前电脑适合的方案、下载大小和可能的处理时间。普通用户完成一次准备后，日常只点提取文案。增强路径不可用时可使用已准备且通过验收的基础路径；若更换识别模式，在设置或结果说明中保留记录，不静默换成未经验证的小模型。

模型准备完成后，已下载视频的转写必须能离线运行；不得在每次提取时临时访问海外模型站点。CPU 设备可能比现有 Mac GPU 样本慢，进度要真实可恢复，不以固定秒数宣传所有电脑的速度。国内云转写可作为后续扩展，不作为第一版 Windows 的必需依赖，也不自动上传用户音频。

### 2.6 简单快速的体验约束

- 下载视频无需安装转写配套或模型；安装引导只在首次需要提取文案时出现。
- 文案服务的初次准备集中在一处：下载对应配套、启动、准备模型、自动连接。重启后提供一个启动入口；日常不要求编辑路径、端口或扩展 ID，也不要求保持终端和结果页打开。
- 提取文案主流程为已识别作品后点击提取，再复制或导出；不在每次操作前询问模型、显卡、术语和人工核对进度。
- 本地服务不可用时，只限制依赖它的文案功能，视频下载保持可用。
- 两浏览器保持相同按钮、结果结构和操作顺序，平台差异集中在首次安装与设置。
- 服务必须仍在运行才可处理任务；关闭页面与退出服务、休眠和关机的影响分别说明，不用简洁界面掩盖真实运行条件。

## 3 开源与私人功能边界

### 3.1 模块职责

| 模块 | 包含的能力 | 对外边界 |
| --- | --- | --- |
| 开源插件 | 页面识别、链接输入、视频下载、文案结果、导出、可选工作台连接 | 不包含个人创作背景、私有素材库和私人 AI 分析 |
| 开源转写配套服务 | Windows 与 Mac 的本地转写、运行环境检测、首次模型准备、任务状态和结果读取 | 可独立运行并分别分发，不依赖私人工作台的代码、数据库、账号或凭证 |
| 私人工作台及服务 | 素材接收与管理、抽帧、AI 拆解、个人背景、方案生成、修改和备份 | 仅供产品所有者使用，不随公开插件发布 |
| 公共连接协议 | 素材身份、来源信息、接收确认和状态查询格式 | 可以公开，使插件连接个人部署的兼容服务；不硬编码私人地址和凭证 |

这些是依赖边界，不要求第一版一定运行三个独立进程。产品所有者可以让同一个本地服务承载配套能力，但公开转写模块必须能够独立安装和运行。

### 3.2 公开插件的独立使用

- 未配置工作台时，核心页面正常提供下载和文案操作，不出现必须注册工作台的提示。
- 下载视频不要求准备 AI 模型或配置 AI 密钥。
- 第一版文案提取使用公开配套的本地服务。模型单独准备，不打包进扩展，也不通过私人工作台提供转写。
- Windows 与 Mac 的配套服务遵循同一接口；基础转写不要求 GPU、访问 Google 服务或配置云 API。
- 本地服务未就绪时，仅文案操作提示安装或启动方式，视频下载保持可用。
- 工作台断连不影响公开插件的下载、复制和导出。
- 插件不提供内容拆解、个人创作建议或面向创作的 AI 聊天。

### 3.3 私人数据与 AI 调用

- 私人素材、数据库、创作背景、生成方案、访问凭证和运行日志不进入公开发布包；原始抓取记录也不作为公开示例。
- 私人工作台默认只在本机使用，不提供公网注册或团队邀请。
- 工作台连接需要配对凭证、明确的调用来源和受控文件入口；不能因为只监听本机就省略访问边界。
- 第一版不会在收集后自动发起付费 AI 分析。分析和生成由用户明确点击触发。
- 现有本地 ASR 负责听写。多模态拆解和创作生成需要另选模型，不能把 ASR 能力视为已经具备创作分析能力。
- 如果选择云 AI，调用前能看见会发送哪些文本或画面。原始视频默认不整段上传，个人背景仅在生成或调整方案时按需发送。
- 配置外部 AI 时，工作台显示服务来源和发送范围；凭证仅由后台使用，不放在插件或页面公开资源中。

开源发布前需核对所用代码、运行组件和模型的许可证及安装说明。模型权重、私人样本和个人配置不因插件开源而自动成为发布内容。

## 4 页面结构

### 4.1 插件快速操作页

首次打开优先识别当前作品。识别失败或当前页面不是作品页时，提供分享链接输入框。

默认展示当前作品的标题、封面、来源，以及下载视频和提取文案两个操作。工作台已配对时，增加收集到工作台；未配对时不占用主界面。

| 区域 | 第一版内容 |
| --- | --- |
| 作品入口 | 当前作品自动识别；分享链接作为备用输入 |
| 核心操作 | 下载视频、提取文案；配对后显示收集到工作台 |
| 处理状态 | 当前阶段、完成或失败、重试入口；不展示内部模型和命令 |
| 文案结果 | 可简单编辑的全文、复制全文、下载 TXT |
| 次级操作 | 导出 SRT、查看来源、打开已收集的素材 |
| 折叠辅助功能 | 清晰度、术语提示、可选细致校对 |

默认界面不出现语音片段计数、模型名称、人工确认进度和双模型分歧，也不让用户选择 Windows 或 Mac 的识别后端。文案只用一条轻量提示说明可能存在识别错误。修改稿与原始识别结果分别保留，复制和导出使用当前稿。

### 4.2 插件设置页

- 本地文案服务是否就绪，以及与当前系统对应的首次准备、模型下载或离线导入、重新启动入口。
- 工作台连接配置、配对结果、断开连接和打开工作台。
- 下载偏好、当前安装渠道、更新方法和必要的兼容说明；运行引擎与设备诊断放在可展开的高级区域。

首次配置集中完成；日常下载和收集不要求反复填写路径、凭证、术语或类别。

### 4.3 工作台素材库

默认展示最近收集，卡片包括封面、标题、来源、收集时间和处理状态。提供标题、作者和文案搜索，以及简单标签和状态筛选。

素材可以添加备注、标签、归档及取消归档。第一版归档不删除媒体，也不删除浏览器原有下载文件。完整素材包导入作为连接失败或迁移时的备用入口。

空状态告诉用户怎样从插件收集；失败卡片直接提供重试，不要求用户查看处理日志才能继续。

### 4.4 工作台素材详情

在一个页面中设置三个明确区域：视频与文案、AI 拆解、生成创作方案。保留原始来源入口，分析结果中的时间点可以定位到视频。

文案支持全文修改；不强制逐句回听和确认。分析显示所使用的文案版本和画面覆盖范围。文案修改后，已有分析保留，并提示其使用的是旧版本，可按需重新分析。

素材尚未准备好时展示当前阶段和已有内容，不能用无依据的结果填充页面。

### 4.5 工作台创作方案

列表包括方案标题、参考素材、创建时间、最后修改时间和草稿或准备拍摄状态。详情包括本次需求、采用的个人背景、创作思路、脚本、分镜和准备清单。

用户可直接编辑，也可提出简短的 AI 调整要求。AI 调整保存新版本，保留此前方案。提供复制和 Markdown 导出，使方案能在其他笔记或拍摄工具中使用。

### 4.6 我的创作背景与设置

第一版保存一套默认背景：账号或领域、目标受众、内容目标、表达风格、常见时长、拍摄设备、可用人员和出镜偏好。字段可留空；缺失时给出可编辑默认假设，不反复要求填写整张表。

设置页还包括 AI 服务配置、素材目录、备份与恢复、本地服务状态。后台技术细节集中在设置与诊断中，不放入创作主流程。

## 5 核心使用流程

### 5.1 公开用户下载与提取

1. 用户在 Edge 或 Chrome 的作品页面打开插件，或粘贴分享链接。
2. 点击下载视频；浏览器保存完整 MP4，完成后显示文件去向。
3. 点击提取文案时，首次未准备服务则显示一次性引导；服务就绪后先保证视频完整，再将转写任务交给当前电脑的本地配套服务，无需每次选择引擎。
4. 用户看到进度，完成后复制或下载文案，也可简单修改全文。
5. 插件结果页关闭后可恢复已接收的任务和结果；不要求私人工作台参与。

### 5.2 产品所有者首次配置

1. 启动本地服务与工作台，完成一次素材保存位置配置。
2. 在插件设置中连接和配对工作台，测试连接成功。
3. 配置 AI 服务及其发送范围；未配置 AI 时仍可收集和查看素材。
4. 可选填写默认创作背景；生成方案前可随时补充。

第一版提供清晰的一次性安装与启动说明。日常处理不要求盯着终端或保持工作台页面打开，但本地服务必须运行。

### 5.3 收集到生成方案

1. 在已识别的作品上点击收集到工作台，不强制填写标签、备注或分析目的。
2. 工作台持久化素材记录后返回素材标识，插件显示已加入素材库，并说明视频或文案仍在准备。
3. 浏览器负责已开始的下载；本地服务负责接收完整文件、保存应用副本、转写和抽帧。下载完成前可关闭插件工具页，但不能把退出浏览器后尚未完成的下载当作后台已接管。
4. 视频完整保存、文案与画面索引准备完成后，素材显示可以分析。
5. 用户在详情页点击 AI 拆解，查看结构、表达和画面观察及其来源位置。
6. 点击生成我的方案，默认带入创作背景；填写本次主题、目标时长和可选要求。
7. AI 生成脚本、分镜、准备清单及借鉴理由，方案关联这条参考素材。
8. 用户直接编辑或提出调整要求，保存为准备拍摄，复制或导出使用。

首次配置完成后，从已识别作品到启动方案生成的主流程只有收集、拆解、生成三个主要按钮动作；填写本次主题与查看结果不计作额外配置步骤。

### 5.4 重复与异常流程

| 情况 | 第一版行为 |
| --- | --- |
| 重复收集同一作品 | 使用同一素材记录；提示已经收集，可打开；失败阶段可以重试 |
| 工作台离线 | 显示尚未收集成功；可以继续下载和导出素材包，之后手动重试或导入 |
| 页面或下载失败 | 展示具体可操作原因；支持重新打开作品或重试，不保存半个 MP4 为成功结果 |
| 视频无音轨或无可识别语音 | 视频保存成功；文案标记无可提取内容，可选择仅画面拆解并明确范围 |
| 只有文案可用 | 允许文案拆解；不输出声称基于画面或完整剪辑的观察 |
| 转写或抽帧失败 | 保留已保存的视频；在素材记录上重试相应阶段 |
| AI 超时、额度不足或调用失败 | 保留原素材和已有版本；提供重试或配置入口，不展示成功占位内容 |
| 关闭工作台页面 | 本地服务继续执行已接收任务；重新打开从持久化状态恢复 |
| 休眠、关机或后台重启 | 任务标记中断或等待恢复；从已完成阶段重试，不承诺断电后持续运行 |
| 修改文案或创作背景 | 已有分析和方案保持历史版本；新结果使用新的输入快照 |

第一版不自动重复发起可能收费的 AI 请求。调用结果不确定时先显示待处理状态，由用户选择重试。

### 5.5 国内用户安装与首次提取

1. 进入项目的国内可访问安装页，选择 Edge 商店安装，或按当前浏览器的图文说明解压并加载 ZIP。安装页标明渠道当前是否已发布，不显示空的商店承诺。
2. 插件安装后可直接下载视频；首次点击提取文案才检测本地配套服务。
3. 根据 Windows x64、macOS arm64 或 macOS x64 选择配套包，启动器检测环境并提供所需模型准备入口，不要求用户安装开发工具。
4. 通过国内下载入口下载模型，或导入离线模型包；未完成下载、磁盘不足或校验失败均显示恢复操作。
5. 插件与配套服务完成授权连接后显示文案提取可用。之后使用 Edge 或 Chrome 都复用同一套本地服务和已准备模型，不重复下载。
6. 重启电脑后通过一个入口启动配套服务。遇到组织策略禁止扩展、操作系统不受支持或硬件不足时给出准确说明，下载功能按其实际可用范围保留。

## 6 任务状态与数据关系

### 6.1 状态含义

素材记录、视频保存、转写、画面准备、分析和方案生成分别保存状态，避免用一个完成标记掩盖中途失败。

| 用户看到的状态 | 含义 |
| --- | --- |
| 已加入素材库 | 工作台已持久化作品身份与来源，视频可能仍未保存完整 |
| 正在保存视频 | 媒体获取或应用副本保存尚未完成 |
| 正在准备内容 | 视频已保存，文案或画面仍在准备 |
| 可以分析 | 当前拆解所需输入已准备好；限制模式明确标注 |
| 正在拆解 | AI 分析任务已接受 |
| 拆解完成 | 分析结果已保存，可以生成方案 |
| 正在生成方案 | 正在根据本次需求与背景生成 |
| 方案已保存 | 可查看、修改与导出完整方案 |
| 需要重试 | 指明失败阶段；此前成功产物仍然可用 |

### 6.2 核心记录

| 记录 | 必需内容 |
| --- | --- |
| 素材 | 平台与作品 ID、来源链接、可获取的标题和作者、收集时间、视频副本及完整性信息、标签与备注 |
| 文案 | 原始识别稿、当前编辑稿、时间段、版本、生成状态 |
| 画面索引 | 图片、对应视频时间、采样覆盖信息 |
| 拆解 | 输入版本、观察和来源位置、可借鉴点、局限、生成时间及所用模型记录 |
| 创作背景 | 默认受众、目标、风格、设备、人员、时长、出镜限制等 |
| 创作方案 | 参考素材和拆解、背景快照、本次需求、脚本、分镜、准备清单、版本和状态 |
| 任务 | 类型、关联素材或方案、阶段、结果、错误和恢复信息 |

同一素材可以保存多版拆解和多份方案，但每次生成只基于一条参考素材。去重以平台和作品 ID 为主，标题相同不能作为去重依据。永久保存的文件由应用管理，不仅引用容易被用户清理的浏览器下载路径，也不只保存会失效的 CDN 地址。

公开素材包建议包含版本说明、作品信息、视频、可用的文案与字幕。允许下载失败或文案缺失的记录作为不完整素材包导入，但必须显示缺失项，不能误标为可以完整分析。

## 7 AI 拆解与创作输出要求

### 7.1 拆解输入与范围

第一版默认使用带时间的文案和采样画面进行多模态拆解。记录实际送入模型的画面时间与文案版本。模型、采样策略和费用上限在选型阶段确定。

输出重点是开场、叙事或论述结构、表达方式、画面如何支持内容，以及可迁移的创作方法。仅有采样画面时不能假装逐帧看过完整视频；音效、音乐和细致剪辑结论也需要相应音视频证据。没有覆盖的部分明确标为无法判断。

第一版不根据标题或少量互动数字自动认定爆款，不把播放效果归因于某个细节。用户收集的是值得参考的素材，爆款原因属于需要进一步验证的判断。

### 7.2 拆解输出

| 内容 | 要求 |
| --- | --- |
| 内容概览 | 说明主题、主要表达和可能服务的受众，推断内容标明依据 |
| 开场与结构 | 描述原视频怎样进入主题、展开和结束，引用有效时间位置 |
| 文案与画面观察 | 区分听写内容、可见画面和解释，不把推测写成实际观察 |
| 可借鉴点 | 解释结构、表达或呈现方法，以及使用条件 |
| 适配边界 | 说明哪些做法依赖人物、场景、资源或事实背景，不能直接套用 |

### 7.3 创作方案输出

方案至少包括目标与创作思路、开场、完整脚本、分镜和拍摄准备。每段分镜说明画面、口播或屏幕文字、大致时长，以及拍摄方式。

方案必须遵守本次需求和个人背景中的明确限制。不能要求单人拍摄者使用未提供的团队、设备或场景。产品事实、价格、功效和用户未提供的经历不凭空补充，必要时使用待填写项。

借鉴理由需连接参考视频和本人的新主题，不能只替换名称、照搬原片内容或给出通用口号。调整要求保存成新版本，历史稿仍然可查看。

## 8 开发顺序与阶段出口

顺序优先解决可靠获取、持久化与独立运行，再验证 AI 输出。阶段出口是后续开发的检查点，本次只完成 PRD。

| 阶段 | 开发内容 | 完成标准 |
| --- | --- | --- |
| 0 范围与选型 | 固定 Edge 与 Chrome 的最低版本、Windows 与 Mac 的硬件范围、跨平台转写模型与输出协议、国内分发渠道、多模态 AI 和验收样本 | 至少验证 Windows CPU 与两类 Mac 的基础引擎可行性；明确最低配置与下载大小；国内渠道、模型与数据发送范围有可执行方案 |
| 1 插件快速获取与公开配套 | 简化双浏览器主界面；适配 Windows 与 Mac 的转写服务；提供三类配套包、一次性准备和后台结果恢复 | 六个浏览器与硬件组合均通过下载和文案检查；无私人工作台依赖；不要求普通用户编译或操作模型命令 |
| 2 持久化与收集 | 多扩展身份配对、工作台接收、媒体副本、去重、最小素材库与任务恢复 | 两浏览器可连接同机服务并独立管理任务；点击收集后得到真实记录；重复和失败可恢复 |
| 3 素材详情与拆解 | 视频与文案、画面索引、全文修改、多模态拆解、来源定位 | 单条素材能产出有来源依据的拆解；输入缺失与 AI 失败处理有效 |
| 4 个性化创作 | 默认背景、本次需求、方案生成、直接编辑、AI 调整、版本和导出 | 生成结果符合资源和风格限制，保存后能够实际用于拍摄 |
| 5 完整验收与公开准备 | 六组合回归、国内网络安装与离线转写、Edge 商店发布准备、备份恢复、公开包隔离、许可证与图文说明 | 各目标组合可在干净环境独立使用；国内安装有真实记录；商店和 ZIP 状态准确；私人实际验收与工程检查分别记录 |

先完成私人使用的真实闭环与跨平台公开功能验收，再决定公开发布时间。第一版公开交付包含双浏览器插件 ZIP、三种系统与架构的配套包、合规的模型准备入口、图文安装与更新说明。面向普通国内用户的正式发布优先推进 Edge 商店审核；审核未通过时只能准确称为手动安装版或内测版。Chrome 商店为补充渠道，不能阻塞已有国内手动安装路径，也不能替代兼容验收。

## 9 验收标准

### 9.1 插件功能与独立性

| 编号 | 验收场景 | 通过标准 |
| --- | --- | --- |
| E01 | 当前作品与分享链接 | 识别目标作品并显示对应信息；非作品页和无效链接得到明确反馈 |
| E02 | 下载完整性 | 成功下载的样本可以完整解码；实际时长、大小、画质有记录，不把界面画质选项当作实际画质 |
| E03 | 文案复制与导出 | 页面当前稿、复制结果和 TXT 内容一致；SRT 格式、顺序和时间范围有效 |
| E04 | 简洁主界面 | 术语、模型信息、分歧提示和逐句确认不占默认主界面；不要求校对后才能复制或导出 |
| E05 | 独立公开环境 | 各目标系统的干净 Edge 与 Chrome 配置中，无私人工作台代码、配置或账号即可下载；准备公开配套后可转写 |
| E06 | 配套服务未启动 | 文案操作说明解决方式；下载功能仍然可用，界面没有无限等待 |
| E07 | 页面关闭与任务恢复 | 本地服务已接收转写任务后关闭工具页，任务继续；重新打开恢复正确作品的状态与结果 |

### 9.2 收集与持久化

| 编号 | 验收场景 | 通过标准 |
| --- | --- | --- |
| C01 | 快速收集 | 已识别作品、服务就绪的本机条件下，从提交到持久化接收确认目标为 2 秒以内；不含页面识别、下载、转写和 AI 时间，连续 10 次记录实测 |
| C02 | 成功状态准确 | 仅接收元数据时显示已加入素材库或处理中；完整内容未准备好时不显示完整分析就绪 |
| C03 | 页面与浏览器生命周期 | 关闭插件或工作台工具页不丢失任务；下载完成并由本地服务接管后退出浏览器，后台任务仍可继续 |
| C04 | 重启与失败恢复 | 服务重启或异常后状态不会永久卡住；在同一素材上恢复或重试，不重复生成素材记录 |
| C05 | 重复收集 | 同一作品通过短链接、直达链接和当前页面重复收集只产生一个素材身份 |
| C06 | 文件与数据独立 | 清理浏览器下载文件或缓存后，已完成收集的工作台视频、文案、拆解和方案仍然可用 |
| C07 | 来源与文件对应 | 来源、作品 ID、视频、文案和生成结果关联正确；标题或作者取不到时保留未知，不猜测 |
| C08 | 备份恢复 | 从备份恢复到新的应用数据目录后，素材播放、原始与编辑文案、拆解、背景和方案均可用 |

### 9.3 AI 与创作质量

| 编号 | 验收场景 | 通过标准 |
| --- | --- | --- |
| A01 | 真实多模态拆解 | 在至少 5 条不同主题样本上，人查看引用的时间和画面；每条至少有 3 个可验证观察点，没有将未送入模型的画面当作观察 |
| A02 | 输入不完整 | 无音轨、文案失败、抽帧失败分别显示有效分析范围；不把文案分析包装成完整音视频分析 |
| A03 | 个性化适配 | 至少 3 条参考素材分别使用两套不同创作背景；方案在受众、目标或拍摄方式上体现对应差异，并满足明确限制 |
| A04 | 可拍摄程度 | 用户能指出开头怎么拍、每段说什么、需要哪些素材；无未说明设备依赖，无虚构产品事实，时长安排合理 |
| A05 | 版本与修改 | 文案或背景修改不覆盖已有来源快照；方案编辑和 AI 调整后可恢复此前版本，导出与当前选择版本一致 |
| A06 | 模型调用失败 | 无凭证、网络失败、超时、额度不足能停止等待并显示可操作状态；不丢素材，不静默循环付费重试 |
| A07 | 个人实际验收 | 产品所有者用至少 3 条真实收集素材完成生成与修改，并确认方案能用于自己的拍摄；仅自动化检查通过不能替代此项 |

### 9.7 转写与简单快速的体验

| 编号 | 验收场景 | 通过标准 |
| --- | --- | --- |
| T01 | 无独立显卡的基础路径 | Windows x64 与 Intel Mac 普通 CPU 设备完成五分钟中文样本的全文转写、TXT 与 SRT；Apple Silicon 基础路径也能独立完成；无需 CUDA 或云密钥 |
| T02 | Apple Silicon 增强路径 | 对同一组样本记录基础与现有 Qwen3 增强路径的正确词、错误、时间和资源；增强依赖缺失时有有效基础路径；不声称与各平台识别文字完全相同 |
| T03 | 离线与后台执行 | 依赖和模型就绪后，已下载的视频断网可转写；关闭结果页仍能完成并恢复；退出服务和休眠等中断有明确恢复状态 |
| T04 | 默认主路径 | 首次准备完成后，已识别作品只需提取文案，再复制或导出；不要求选择引擎、显卡、术语或逐句确认；默认不额外执行第二模型对照 |
| T05 | CPU 性能与质量 | 在最低配置和推荐配置设备记录至少 30 秒、一分钟、五分钟样本的用时、内存与磁盘；同组中文、术语和数字样本做人工抽查，阶段 0 固定可接受门槛；不以 Mac GPU 结果承诺普通 CPU 速度 |
| T06 | 部分能力不可用 | 模型未准备、系统不支持、服务未启动、增强路径失败分别给出明确下一步；可用的视频下载保留；不无限等待，不静默下载大模型或上传音频 |

首发主体验使用同一组至少 10 条不同作品跨六个支持组合验证，包含短链接、直达链接、当前页、中文口播、英文术语、无语音或音乐视频。另需覆盖无效链接、需登录、下载中断、重复收集、服务离线、AI 失败和重启恢复。受限或不可访问作品验收的是正确失败反馈，不要求全部下载成功。私人工作台的实际创作验收在产品所有者的 Mac 上完成；公开组合不能因私人流程通过而自动标为通过。

输入上限沿用原型的一小时和文件大小检查；如果公开宣称一小时支持，必须额外完成接近上限的样本与超限拒绝测试。没有完成时，按实际验证范围说明支持程度。

处理速度记录电脑、模型、输入时长和各阶段用时，不用现有一条五分钟视频的约 24 秒记录承诺全部作品。工程稳定性、转写质量、AI 输出质量和个人拍摄可用性分别记录。

## 10 当前原型与第一版的差距

现有项目已有 Chrome 扩展、页面媒体获取、本地转写、结果恢复、全文和字幕导出、逐句回听及编辑能力。已记录的真实闭环集中在本机 Chrome 的一条五分钟样本，不能直接视为公开插件已通过多环境验收。

| 差距 | 第一版需要补齐 |
| --- | --- |
| 默认界面偏重精校和技术信息 | 简化主路径，辅助功能折叠 |
| 当前转写流程要求工具页保持打开 | 页面之外的任务衔接和持久化恢复 |
| 当前只在 Apple Silicon Mac 的 Chrome 上记录了单样本闭环 | Edge 与 Chrome 的六组合验收，以及两浏览器扩展身份与连接适配 |
| 当前精校入口依赖 Mac 的 MLX 与项目内 Python 环境 | Windows 与 Intel Mac 的 CPU 基础路径、统一输出和系统运行适配 |
| 依赖位于开发目录，尚非独立分发包 | 三类系统配套的安装、数据目录、启动方式、国内模型准备与离线导入 |
| 当前发布包没有国内多渠道安装与更新闭环 | 国内可达下载页、双浏览器 ZIP 图文说明、Edge 商店状态及升级恢复验证 |
| 没有私人素材库 | 工作台、媒体副本、身份与去重、搜索和备份 |
| 没有创作拆解与方案生成 | 多模态分析、个人背景和创作方案功能 |
| 公开与私人内容尚在同一研究工作区 | 发布结构隔离，私人数据不进入公开仓库或发布包 |

原型事实以项目 [README](../README.md)、[插件说明](../outputs/douyin-independent-extension/README.md) 和 [精度实测](../outputs/文案精度优化验证.md) 为依据；这些原型结果不等于本 PRD 的验收项已经完成。

## 11 开发前需要确定的选项

| 选项 | 本 PRD 的建议默认值 | 确定时点 |
| --- | --- | --- |
