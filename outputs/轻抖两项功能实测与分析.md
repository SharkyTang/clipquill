# 轻抖两项功能实测与分析

核查日期：2026-10-12。样本：https://v.douyin.com/bbXEZdKRShg/

## 结论

轻抖网页端的“抖音链接 → 视频下载”和“抖音链接 → 视频语音文案”均已通过正常界面完成一次测试，并取得本地文件。可以还原前端如何提交任务、查询结果、下载和导出；没有取得轻抖服务器源码，也没有确认其抖音解析服务或语音识别供应商。

用户已打开微信轻抖小程序，但电脑控制工具两次读取该应用窗口均超时。本报告的运行证据只适用于网页端，不能视为小程序端已验证。

## 已确认的前端流程

### 视频下载

1. 页面将输入整理成带序号和 URL 的列表。
2. 调用创建任务接口，获得批次标识。
3. 按批次获取任务结果。前端代码配置约 3 秒轮询，并在页面隐藏时暂停相应轮询。
4. 从成功结果使用 `noWatermarkUrl`。
5. 浏览器获取视频字节，生成 MP4 文件并保存。

浏览器实际观察到创建任务、读取任务列表以及字节系视频 CDN 资源。公开脚本中也存在直接获取视频字节并保存文件的实现。所核查的前端下载路径没有进行逐帧像素擦除；服务器是否曾对素材作画面处理仍未知。

分辨率选项需要特别处理：代码对默认 1080P 分支直接使用已有 `noWatermarkUrl`，对部分其他分辨率才请求指定分辨率地址。因此界面显示“1080P”不是实际文件分辨率的证明。本样本的默认导出结果确实是 720P。

### 文案提取

1. 页面整理同类输入列表并提交文案任务。
2. 服务返回批次标识，页面按批次查询文案结果。
3. 页面分别展示作品标题、作品时长、文案内容和摘要入口。
4. 选中任务后可导出为 XLSX、CSV 或 DOC；同步导出赞评转数据为单独选项。
5. 本次选择 CSV，未勾选附加数据选项；服务生成文件后提示在 24 小时内下载，正常下载成功。

返回内容符合语音转写的用途，且存在同音和专有名词错误。但这些现象不足以证明后台具体使用哪家 ASR、是否读取已有字幕、是否利用缓存或是否经过大模型后处理。

## REA 实际运行及限制

- 在项目工作目录内隔离安装并运行 `rea-agents@6.4.0`，未执行全局 setup 或修改 Codex 的 MCP 配置。
- 对 9 个页面及共用 JavaScript 文件和 1 个本地验证元数据文件运行静态分析；目标脚本没有被 REA 执行。
- 解析了 9 个 JavaScript 文件、159 个模块，解析失败数为 0。
- REA 返回了分析结果，但明确报告部分语义图和调用关系因结果预算限制未完整展开。不能称为完整源码恢复或完整程序分析。
- 公开主脚本另外进行了定向人工静态核对，用于确认接口定义及轮询配置；它不在上述 9 个脚本的 REA 统计中。
- 首次运行被 macOS 编译缓存的沙箱写入限制阻挡；经授权重试后完成。

## 实现同类功能仍需解决的部分

现在已掌握客户端的操作和状态流程。如果要独立开发同类工具，仍需确定合法可用的视频解析来源、媒体下载权限，以及语音识别服务和成本。仅复制这些前端请求不能获得后台能力，更不能保证接口稳定或可供第三方产品使用。

独立实现的验收应检查：实际分辨率与文件时长、视频和音频完整性、链接失效及权限不足的错误反馈、识别正文与作品标题的区分、专业词汇转写质量、导出文件有效性。当前样本只是一次成功闭环，不代表所有抖音视频均可处理。
