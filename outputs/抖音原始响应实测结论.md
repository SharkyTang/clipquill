## 本轮结论

已经绕开对轻抖服务的依赖，直接从用户正常登录、正常播放的抖音网页中读到了这条作品的媒体元数据。当前样本的下载开关为 `false`，因此本轮止于解析与核对，没有利用播放地址绕过下载限制。

这次获得的是“真实样本的解析成功”，尚不是“任意抖音分享链接一键导出成功”。无水印状态也不能仅凭字段名认定。

## 原视频数据究竟在哪里

这次刷新原作品后，页面文档返回 HTTP 200，HTML 中的 `script#RENDER_DATA[type="application/json"]` 包含经过 URL 编码的 JSON。解码 JSON 后，目标对象位于 `app.videoDetail`，其 `awemeId` 与分享链接对应的作品 ID 完全一致。

这条路径不需要假定存在另一个详情请求，也不需要重放带签名的私有接口。网页已经将播放所需的初始化数据放在响应里。本次成功依赖正常浏览器会话，不能推断匿名服务器请求也一定成功。

| `awemeId` | `7689864994510343451` | 必须匹配原作品，排除预加载推荐视频 |

播放地址涉及 `v5-hl-mly-ov.zjcdn.com`、`v3-dy-o.zjcdn.com` 等 CDN。导出的公开分析只保留域名和地址摘要，不发布完整带参数地址。

此前看到的下载按钮不可用，现在有响应中的下载开关作为佐证。但单凭这一份响应仍不能归因于作者设置、客户端策略或其他具体原因，也不能推出所有设备的下载规则相同。

## “去水印”的技术判断

可以独立实现的通用路径是：解析分享链接 → 获取正常可访问的作品数据 → 核对作品与下载许可 → 选择适合的现成媒体版本 → 下载或合并音视频 → 校验时长、内容和水印。

本样本的 `normal_720_0` MP4 标记为 H.264、1280 × 720、27,594,766 字节。之前轻抖导出的本地文件恰好也是这个分辨率、编码、时长和字节数。这支持“轻抖获取了抖音现成视频版本”的推断，尚未做同源文件的字节比对，不能宣称已经证明轻抖内部实现。

MP4、DASH 或 `playAddr` 的名字都不能证明视频没有水印。只有实际获准导出的文件，经过画面核对后才能给出水印结论。写在作者原始画面中的文字、标识和字幕也不应与平台下载水印混为一谈。

## “视频文案”如何独立实现

这次目标对象里有 374 字的 `caption` 和 132 字的章节摘要。它们对应发布说明和摘要，不是完整口播逐字稿。本次响应中未发现完整字幕或 ASR 逐字稿；这不等于平台的其他界面永远不提供字幕。

独立转写链路已经用本地文件验证：FFmpeg 提取音频 → Whisper large-v3-turbo Q5_0 + Silero VAD → TXT / SRT / JSON。之前完整 5 分钟样本的实测总耗时为 44.595 秒，生成 92 段、1514 字原始转写。这些是此前保存的实测清单结果，本轮没有重复转写。

转写本身不调用轻抖或云端语音接口；测试输入当时来自轻抖导出的文件，所以不能把该实验写成“已经独立完成抖音链接到文稿的全过程”。专有名词仍有识别错误，输出需要校对。

## 后续实施步骤

1. 换用自有或已获授权、且平台允许下载的样本，验证下载和无水印状态；当前样本不越过下载限制。
2. 将分享链接解析、正常页面获取接到已验证的数据解析器，明确区分登录要求、作品不存在、验证码或访问拒绝，不伪造签名、重放他人凭据或绕过风控。
3. 下载前检查许可，优先选择兼容的完整 MP4；需要分离音视频时校验关联信息、时长及格式后再合并。
4. 将校验后的文件交给本地转写模块，组合成一键操作；失败时返回真实原因，不用其他视频顶替结果。

REA 的作用仍是辅助静态代码和调用流程分析。本轮关键突破来自正常页面的响应数据，既不需要解包微信小程序，也不意味着获得了轻抖后端源码。独立实现应使用自己的界面、业务代码和获准使用的模型/组件。
