# 文案识别精度优化实测

2026-10-12，本机 Apple M5 Pro / 48 GB。扩展已更新并跑通真实浏览器流程。没有承诺或测得 100% 准确率。

## 选择依据

对同一份 300 秒 MP4 分别运行原 Whisper Turbo Q5、增加术语的 Turbo、完整 Whisper large-v3、增加术语持续提示的 large-v3，以及 Qwen3-ASR 1.7B。完整 Whisper 仍有多处中文同音词及英文名称错误；最后选择 Qwen3 为主识别，Whisper Turbo 为独立对照，仅标出分歧，绝不直接覆盖主识别。

Qwen3 不加术语时，已正确识别“抽帧”“关键帧”“权限”“手中的工具”，但仍将 Claude 识别为 Cloud。真实浏览器验收时明确输入了 `OpenAI, Claude, Opus 5.5, GPT-6 Astra, Ultra, 关键帧, 抽帧, 生图`，英文改善包含术语提示的贡献，不应归因于模型单独提高。

原视频 SHA-256：`3de51b86b8bf24adbab5e1abab5be94bf3d91f042f00dee0c3c46083c0a18ecb`。旧稿与新稿来自相同字节的音视频，没有替换样本。

## 工程验收

- 原始短链接 → 正常作品页 → 完整 MP4 → 本地识别 → 页面自动显示：成功。
- 本地处理 23.861 秒，122 段，40 段提示重点检查。提示数不等于错误数，模型一致也不代表正确。
- 原始旧版 CPU 转写为约 46–49 秒；新版使用 GPU，不能把速度变化单独归因于模型。
- 回听第 1 段及第 28 段成功：播放器显示播放状态，后者定位 80.502 秒并在片段末尾暂停。
- 单句改字后全文同步，TXT/SRT 实际下载均包含“成片”，不再包含该句“成天”；重新打开工具可恢复。
- 确认计数可勾选及取消。重新编辑取消确认、旧稿不可被改写、错误任务不能恢复草稿、两种导出一致等行为由测试覆盖。
- 自动化测试：20 项 JavaScript、28 项 Python，共 48 项通过。
- 音频接口仍限制 Origin / Host、完成任务、固定音频路径，拒绝符号链接。识别和回听不依赖外部服务。

记录：`extension-accuracy-validation.json`。截图：`文案精校实测.png`。当前任务结果：`extension-transcripts/7689864994510343451-c9c5488682b94ee1876cb9ba9adb2976/`。后续小修增加了异常长时间片段提示和长视频输出截断检查，未改变识别文本；测试报告保留原始任务计数。

## 实现与来源

主识别调用本机 Qwen3-ASR，ForcedAligner 为原始文字补充时间；分段时保留原文和标点。Whisper 另行识别，归一化对比只用于提示，未做文案润色或凭空补字。所有模型在加载后以离线模式运行，未上传视频或音频。

- [Qwen3-ASR 官方项目](https://github.com/QwenLM/Qwen3-ASR)
- [MLX-Audio 的 Qwen3 识别与对齐文档](https://github.com/Blaizzy/mlx-audio/blob/main/mlx_audio/stt/models/qwen3_asr/README.md)
- [Whisper.cpp 官方项目](https://github.com/ggml-org/whisper.cpp)

模型文件的版本与 SHA-256 已记录于 `asr-model-provenance.json`。MLX-Audio 固定为 0.5.8，依赖版本清单在项目 scripts 中。完整 Whisper 模型仅供对比实验，没有被误设为默认引擎。
