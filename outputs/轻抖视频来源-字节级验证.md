## 核心结论

**独立获取的抖音 MP4 与轻抖导出文件完全一致。** 对本次样本，获取平台已有的播放版本即可得到轻抖导出的同一成品，不需要重新编码或用图像模型擦除水印。

这推翻了上一轮仅凭 `download.allowDownload: false` 就停止技术访问验证的过强判断。该字段表示网页下载入口状态；实际 CDN 请求另有访问结果。本次保持原始地址不变，未提取账号 Cookie、添加 Authorization、伪造签名或修改网页开关，普通 GET 就取得了文件。

## 轻抖做了什么、还不能确定什么

公开前端代码已确认：任务结果给出 `noWatermarkUrl`，浏览器 `fetch` 获取字节，用 `Blob` 保存成 MP4。结合本次哈希证据，能够确认本样本输出来自现有媒体版本，且客户端没有另做像素修复。

轻抖服务器的“链接 → 媒体地址”入口仍未确定，可能采用不同页面、服务接口或缓存；本轮没有服务器源码和后台请求记录，不能声称已逆向其全部后台。但独立实现无需复制这一黑盒：正常页面已提供本样本所需的数据。

## 已完成的独立实现

1. 离线 HTML / HAR / JSON 解析器：精确匹配作品，识别媒体版本。
2. 原样播放地址 → 完整 MP4：真实网络请求、文件参数与哈希验证已完成。
3. 本地 Chrome 扩展原型：粘贴链接、正常打开抖音页、读取作品数据、选择 MP4、交给浏览器下载、检查完成状态和文件大小。
4. 扩展 14 项核心测试通过；真实保存响应的离线选择结果也与实际下载地址一致。
5. **扩展已安装，原始短链接的一键流程已验收。** 在扩展页面粘贴 `https://v.douyin.com/bbXEZdKRShg/` 并点击“解析并下载”，自动保存了 27,594,766 字节的 720p、300 秒 MP4。读取 Chrome 下载目录中的实际文件，完整 SHA-256 与上表完全相同。没有在本次流程调用轻抖。

安装后的真实测试修复了两个问题：分享短链接经过 iesdouyin.com 中间页，跨域 fetch 受浏览器限制，现改用普通标签页跳转；`/video/:id` 直达页首屏不含作品数据，现对同一作品正常打开已观察的 `/user/self?modal_id=:id` 弹窗页一次。作品 ID 全程保持为字符串并严格核对，不回退到其他推荐视频；没有扩展站点权限范围。

匿名 HTTP 客户端能把短链接解析到正确作品 URL，但本次拿到的 HTML 没有作品媒体数据。因此“纯服务器、无需浏览器和登录的任意链接下载服务”仍未验证。扩展原型使用用户正常的浏览器页面，不复制账户凭据。

本次只验收了当前已登录 Chrome 会话中的该样本 720p 短链接流程。后续还需验证其他作品、未登录状态、1080p、已有页面入口与地址过期情况。本地完整转写已有 TXT/SRT/JSON 结果，其输入 SHA-256 与本次独立下载完全一致；转写尚未接入扩展的一键界面。
